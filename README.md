# ТКПСТ · админ-панель

Админка группы **ИС-25-3С**: вкладки «Изменение расписания», «Посещаемость» и «Пользователи». Вход по паролю
(администратор, староста, куратор).

**Адрес:** https://wtfhoshi.github.io/tkpst-admin/ — GitHub Pages, открывается в России без VPN.
Настройка (только администратор): https://wtfhoshi.github.io/tkpst-admin/setup.html

## Как устроено (своего сервера нет)

- `public/` — страницы панели (без сборки). Публикуются на GitHub Pages workflow-ом `.github/workflows/pages.yml`
  (сначала тесты — если упали, на сайт ничего не уходит).
- `public/backend.js` — «сервер» прямо в браузере: те же адреса, что были у сервера на Netlify, но данные
  читаются и пишутся через GitHub API.
- **Данные** (ФИО, отметки, настройки курсов) — в ПРИВАТНОМ репозитории `WTFHOSHI/tkpst-admin-data`,
  каждый файл зашифрован AES-256-GCM ключом данных. В репозитории — только зашифрованный текст.
- **`public/vault.json`** — «сейф»: на каждую роль одна запись, зашифрованная её паролем (PBKDF2-SHA256, 600 000 итераций).
  Внутри — ключ GitHub и ключ данных. Паролей нигде нет. Создаётся на странице настройки, загружается в `public/` вручную.
- **Изменения расписания** пишутся в `web/overrides.json` публичного `tkpst-schedule` (как и раньше, открыто —
  это расписание для всех).
- Ключ GitHub — fine-grained, только `tkpst-admin-data` и `tkpst-schedule`, `Contents: Read and write`.
  Когда истечёт — «Настройка» → вставить новый (пароль администратора нужен, ключ данных сохраняется).
- Вход: галочка «Запомнить на этом устройстве» — на 1 день; без неё — до закрытия вкладки.
- `public/js/core.js` и `public/style.css` — копии из `tkpst-schedule/web`; при изменении там — скопировать сюда.
- `public/att-logic.js` — правила отметок и списка студентов (общие для браузера и тестов).

## Безопасность — что важно

- Пароли — длинные и разные: сейф публичный, и слабый пароль можно подобрать перебором.
- Права ролей (куратор не меняет настройки и не импортирует) проверяются в браузере. Технически у каждого,
  кто знает пароль, есть ключ на запись в данные — выдавать пароли только своим.
- Сменить пароли (например, если куратор сменился): «Настройка» → новый `vault.json` → загрузить в `public/`.

## Старый сервер (Netlify)

`netlify/functions/att/` и `netlify.toml` — старый сервер на Netlify (проект `tkpst-poseshchaemost`). Нужен только
для переноса данных: открыть `https://tkpst-poseshchaemost.netlify.app/setup.html` через VPN, создать сейф и нажать
«Перенести данные». После переноса проект на Netlify можно удалить вместе с этой папкой.

## Общий вход и пользователи личного кабинета

Для всех трёх разделов используется одна форма и существующие пароли сейфа: администратор, староста, куратор. Вход в любой вкладке действует в остальных; общий выход завершает сеанс. Пароль не сохраняется. Галочка «Запомнить» сохраняет общий `admin_session` на 1 день в localStorage, без галочки используется sessionStorage (максимум 1 день). Старые сеансы администратора без серверного токена требуют одного повторного входа после обновления.

Основной вход проверяет пароль локально по прежнему сейфу и сразу открывает админку, независимо от доступности сервера ЛК. В фоне сервер ЛК на Render также проверяет его пароль по административной записи публичного сейфа и выдаёт случайный bearer-токен. Он хранится внутри того же `admin_session`, с тем же сроком и выбором запоминания. Обычная cookie студента и роль, переданная клиентом, административных прав не дают. В БД находится только хэш токена. Смена сейфа отзывает доступ.

В `#users` администратор может искать зарегистрированные аккаунты, фильтровать подтверждённые/непривязанные, просматривать страницы и раскрывать карточку для подтверждения принадлежности студенту. Куратор и староста видят объяснение ограничения доступа и могут перейти к посещаемости.

Список студентов читается существующим backend из зашифрованного приватного `config.json`; после расшифровки в браузере минимальные поля (id, курс, ФИО, группа, даты поступления/выбытия) синхронизируются с Neon через защищённый API. Перед чтением выдаётся одноразовый серверный билет с монотонным номером; это исключает перезапись свежего списка задержанным старым ответом. Повторное использование и чужой билет отклоняются. Кнопка «Обновить список» использует общий вход, без повторного пароля. Пароли, ключ GitHub, ключ данных и отметки посещаемости не сохраняются на сервере.

Привязку подтверждают после проверки личности, отдельно для конкретного аккаунта и студента. Введённое при регистрации имя ничего не подтверждает. Один студент одного курса связан максимум с одним аккаунтом. Подтверждённые ФИО и группа доступны только в собственном ЛК. Выбывший/удалённый студент теряет подтверждение после актуализации списка. Первый вход в «Пользователи» требует успешной синхронизации: ошибка источника не позволяет обходным запросом использовать старый список.

Для изолированной браузерной проверки без реальных данных: `node test/preview.mjs` → `http://127.0.0.1:4181/#users`. Пароли тестового стенда описаны в самом скрипте; он подменяет источники только на localhost и не обращается к рабочим сервисам.

## Сетевой доступ и удаление

API личных кабинетов: https://tkpst-api.onrender.com/api/admin/ (Render, free, Frankfurt; та же Neon). Недоступность API не блокирует вход, расписание и посещаемость. Сетевые операции имеют предел ожидания, включая чтение тела ответа. Запуск бесплатного Render после простоя может занимать около минуты; в Users показывается отдельный статус и повторное подключение без блокировки остальных разделов.

Администратор может удалить аккаунт из раскрытой карточки Users, введя точный логин. Аккаунт, его сеансы и связь со студентом удаляются атомарно; студент и посещаемость остаются. Старая карточка не может удалить новый аккаунт с тем же логином благодаря проверке id.

В Attendance → Students остаётся обратимое «Убрать», а новое «Удалить» требует точного ФИО. ФИО и дополнительные поля удаляются из текущей записи; id и даты остаются как анонимная запись «Удалённый студент» для исторических отметок, включая день удаления. Восстановить исходное имя невозможно. При синхронизации такая запись исключается из каталога ЛК и связь снимается; сам аккаунт остаётся. При сбое синхронизации интерфейс сообщает, что источник уже изменён, и предлагает обновить каталог в Users. GitHub история старых зашифрованных версий не переписывается.
